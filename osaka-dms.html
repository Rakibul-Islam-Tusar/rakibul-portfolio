System architecture

One operational core, delivered across web and field teams.

The web portal follows an MVC and repository-based structure, while a separate ASP.NET Core API exposes the same distribution domains to mobile users. Shared data contracts connect both channels to company- and branch-aware SQL Server operations.

Authentication & authorization

Identity is resolved before operational data is exposed.

Login combines user credentials with a selected company. The resulting user, company, token, and branch context are carried through claims/session and used to build an assigned menu and scope transactions.

  1. 01Select companyLogin begins with an explicit operating-company boundary.
  2. 02AuthenticateASP.NET Identity validates the user; mobile/API access issues a JWT bearer token.
  3. 03Resolve accessUser and role mappings determine the permitted menu and actions.
  4. 04Choose branchActive branch context scopes codes, records, and operational workflows.
  5. 05Operate safelyAuthenticated web/API requests carry the established context.
  6. 06AuditUser, branch, timestamps, and transaction status support traceability.

Distribution workflow

Data moves from planning to delivery—without losing branch context.

The system manages both master and transactional data, so operational teams work from one connected source instead of disconnected sales, stock, route, and delivery records.
